## 1. Цель
Создать максимально автоматизированную систему производства вирусных русскоязычных YouTube Shorts о GTA 6:
поиск темы → сценарий → подбор игровых и мемных материалов → озвучка → монтаж → субтитры → контроль качества → готовый MP4.
Главный приоритет — сильный авторский ролик, а не зелёная галочка CI.

## 2. Творческое направление
- Полноэкранный вертикальный формат 9:16, целевой размер 1080×1920.
- Ориентир длительности около 30 секунд, если сценарий не требует иного.
- Провокационный хук с матом в первые секунды.
- Абсурдный, дерзкий, постироничный юмор, brainrot и неожиданные повороты.
- Основа визуала — GTA 6 / GTA-геймплей.
- Мемные видеовставки должны быть реальными и уместными по смыслу, а не случайными карточками.
- Быстрый монтаж, частая смена планов, зумы, тряска и акценты по смыслу.
- Крупные динамичные синхронные субтитры с выделением ключевых слов.
- Приоритет озвучки — живой голос пользователя. Пока нет предоставленного образца и проверенного способа интеграции, синтетическую озвучку прямо обозначать как синтетическую.
- SFX поддерживают шутки и монтаж; музыка не должна заглушать речь.
- Не начинать с логотипов, предупреждений Rockstar или длинных заставок.
- Не использовать узкую горизонтальную полоску геймплея на размытой подложке.
- Не выдавать случайный набор кадров под роботизированную озвучку за готовый ролик.

### Зафиксированное решение
Полицейские/bodycam-вставки из реальной жизни исключены из текущей концепции. Не возвращать полицию, bodycam, сирены или bodycam_finder.py без нового прямого решения пользователя.

## 3. Правила работы
- Общаться по-русски, прямо и без лишней воды.
- Перед каждым действием проверять, можно ли выполнить его самостоятельно через подключённые GitHub-инструменты.
- Минимизировать ручные действия пользователя; не просить скачивать/загружать файлы, если артефакт можно получить через GitHub.
- Перед изменением кода читать актуальную версию файла из GitHub и фиксировать SHA.
- После изменений проверять Actions, логи, артефакты и реальный MP4/WAV.
- Не запускать повторный долгий рендер без установленной причины.
- Если обязательных материалов нет, останавливать сборку с понятной ошибкой.
- Не называть ролик готовым до проверки изображения, звука, субтитров, темпа и вставок.
- Если коннектор не поддерживает нужное действие (например, ручной workflow dispatch), честно сообщать и просить пользователя выполнить только этот шаг.

### Ограничения текущего fallback
- Edge TTS выполняет до трёх попыток.
- При повторном отказе используется gTTS.
- gTTS не поддерживает применённые Edge TTS rate/pitch пресеты, поэтому голос и характер подачи могут отличаться между репликами.
- Текущая тестовая сборка не содержит лицензированную музыку и финальную библиотеку SFX.
- Настоящий голос пользователя не подключён.

## 8. Чек-лист качества каждого видео
Не считать сборку успешной только по статусу Actions.
1. MP4 существует, открывается и имеет ожидаемую длительность.
2. Корректные кодек, разрешение и вертикальный кадр; изображение действительно заполняет экран.
3. В первые 1–2 секунды есть сильный хук.
4. GTA-геймплей присутствует и не выглядит случайным набором кадров.
5. Мемные вставки реально присутствуют и уместны по смыслу.
6. Монтаж динамичный, но не хаотичный.
7. Субтитры синхронны, крупные и не обрезаны.
8. Голос разборчивый; музыка и SFX не мешают.
9. Нет пустых/чёрных кадров, зависаний, ошибок рендера и посторонних заставок.
10. Только после визуального и звукового просмотра можно дать оценку готовности.

## 9. Ближайшие шаги
1. Пользователь прослушивает MP3-превью аудиопрототипа и оценивает естественность/тембр.
2. Исправить стратегию TTS так, чтобы все реплики одного ролика звучали одним голосом; не считать смешение Edge TTS + gTTS production-ready.
3. После выбора стабильного голоса добавить музыку/SFX с нормальным балансом и ducking.
4. Только после аудио-апрува интегрировать аудиодвижок в основной монтаж.
5. Отдельно проверить последний video workflow run и его артефакт; не делать повторный рендер без необходимости.
6. После существенных изменений обновить этот документ и AUDIO_ENGINE.md.
